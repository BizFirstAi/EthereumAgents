EthereumAgents

Ethereum community node for BizFirst.Ai — reads and signed writes across Ethereum and any EVM-compatible chain (Polygon, Arbitrum, Optimism, Base) as workflow steps, via Nethereum over JSON-RPC.

What it does: The Ethereum node (ethereum) wraps JSON-RPC (via Nethereum) as BizFirst.Ai workflow operations across ten resources — account, block, transaction, token (ERC-20), nft (ERC-721), contract, ens, gas, wallet, and utility — 64 defined operations. Unlike many read-only community blockchain nodes, this one ships real signed writes: token transfers, contract calls, NFT transfers, contract deployment, and off-chain message signing, each authenticated with a vault CRYPTO_WALLET credential.

Known gaps: account.history needs an Etherscan-compatible indexer API that isn't wired up — standard JSON-RPC has no method to list an address's past transactions, so it fails clearly with INDEXER_NOT_CONFIGURED. contract.logs is fully implemented in the service layer but its case in the operation-routing switch is currently commented out, so it isn't reachable through the node today (a wiring gap, not a missing feature). 63 of the 64 defined operations are reachable now.

Configuration & Networks

Chain-agnostic by design — any EVM-compatible network works via a plain JSON-RPC URL and chain ID, configured under the Ethereum:Networks application setting:

  • ethereum — Ethereum mainnet (default network, chain ID 1)
  • polygon, arbitrum, optimism, base — popular L2s/sidechains, same node code
  • sepolia — Ethereum's public testnet, free faucet ETH
  • any local dev chain (Anvil/Hardhat/Ganache) or private/enterprise EVM chain

Every operation accepts a network config key, defaulting to Ethereum:DefaultNetwork. Write operations additionally require a credentialID config key pointing at a vault CRYPTO_WALLET credential — the signing key is never a plain config field. Provider API keys should be kept out of plain RpcUrl values — use RpcUrlCredentialId (a vault SERVICE_URL credential) for any endpoint that embeds a secret.

Roadmap

account.history needs an Etherscan-compatible indexer integration. contract.logs just needs its routing switch case re-enabled. Trigger nodes (block/transaction/contract-event/interval listeners) are an open architectural question, out of scope for this action-node build. ENS resolution is a manual implementation cross-checked against the EIP-137 test vector, flagged for further verification beyond plain-ASCII .eth names on mainnet.
